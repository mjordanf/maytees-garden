Account Creation

New customers register at /auth/register. Passwords are bcrypt-hashed server-side. A welcome email fires immediately upon success.

  • Full Name, Email, Password (8+ chars), Phone (optional)
  • Newsletter checkbox triggers double opt-in flow
  • On submit: POST /api/auth/register

  • Redirects to /portal on success

Slide 6 · Customer Flow 04
Authentication

Login

NextAuth.js credentials provider with JWT session strategy. Sessions persist 30 days. Role is embedded in the JWT on login.

  • Email + password → POST /api/auth/callback/credentials
  • bcrypt.compare validates password hash
  • JWT callback injects token.id and token.role
  • Forgot password → 1-hour reset token emailed
  • Redirect: customer→/portal, admin→/portal (Admin Panel link in nav)
Role-based redirect: All roles land at /portal. Superadmin can navigate to /superadmin. Admin/staff see an "Admin Panel" link in the portal sidebar. Role changes take effect on next login (JWT refresh).

E-Commerce · Checkout Step 3

Checkout: Payment

Square Web Payments SDK renders an iframe card form. Card is tokenized client-side; only the token is sent to the server — PCI compliant.

  • Square SDK loads from web.squarecdn.com
  • Client tokenizes card → sourceId
  • POST /api/store/checkout with sourceId + cart
  • Server validates stock, charges Square, decrements onlineStock
  • Atomic Prisma transaction prevents overselling
Sandbox test card: 4111 1111 1111 1111, any future expiry (e.g. 01/29), any CVV (123), any ZIP. Ensure SQUARE_ENVIRONMENT=sandbox in dev.

Admin Panel · Availability

Blocked Dates

The Blocked Dates tab creates AvailabilityOverride records that gray out specific dates on the booking calendar regardless of the weekly template.

  • Date picker + optional reason (admin-facing only)
  • Blocked dates show as unavailable in /booking calendar
  • Existing bookings on blocked dates are NOT cancelled
  • Delete with × button → DELETE /api/availability/overrides/[id]
  • Reason field is for internal reference — not shown to customers
Use case: Block vacation weeks, public holidays, or days when Maytee has other commitments. The override record has isBlocked: true which the slots endpoint checks before returning available times.

System · Email

Email System Overview

All transactional emails are sent via Resend from noreply@mayteesgardencenter.com. The domain is verified via GoDaddy DNS. 15 distinct email triggers across the system.

  • All functions live in src/lib/email.ts
  • Safe fallback: if RESEND_API_KEY not set, logs to console only
  • 24-hour reminder runs via Vercel cron at 10AM UTC daily
  • Newsletter: only confirmed: true subscribers receive broadcasts
  • From: "Maytee's Garden <noreply@mayteesgardencenter.com>"
Free tier: Resend provides 3,000 emails/month and 100/day — sufficient for typical boutique garden center volume. Password reset tokens expire after 1 hour. Test email at /admin/test-email.

Calendar Integration

Microsoft Graph API syncs confirmed bookings to info@mayteesgardencenter.com Outlook calendar using client credentials (no user sign-in required).

  • Azure AD App: "Maytees Garden Calendar" registered at portal.azure.com
  • Permission: Calendars.ReadWrite (Application, admin-consented)
  • Auth: client credentials flow → access token valid ~1 hour
  • Create on confirm · Update on edit · Delete on cancel
  • Graceful no-op if env vars not set — bookings still work
Event includes: customer name, email, phone, ZIP, service, consultation type, video call link (if video), customer notes, and a 60-minute calendar reminder. Event ID saved as Booking.calendarEventId.

Super Admin · Users

Super Admin: User Management

Full user CRUD at /superadmin/users — create accounts, edit roles, reset passwords, and delete users. Role badges are color-coded by level.

  • Amber = Superadmin · Green = Admin · Blue = Staff · Gray = Customer
  • New User: create with name, email, temp password, role, phone
  • Edit: update name, role, phone — role change takes effect next login
  • Delete: user deleted; associated bookings/orders set userId = null
  • All actions call /api/admin/users and /api/admin/users/[id]
JWT sessions are not invalidated immediately on role change — the updated role takes effect when the user's current JWT expires or they log out and back in. Inform users to re-login after a role change.

Super Admin · Password Reset & Settings

Password Reset & Website Settings

Two critical super admin operations: resetting user passwords out-of-band, and viewing (currently read-only) website configuration.

  • Reset Password: enter new temp password → bcrypt.hash stored in DB
  • Communicate temp password to user out-of-band (secure channel)
  • User should change via Forgot Password flow after first login
  • Settings page: read-only business name, address, phone, email, hours
  • Phase 2: settings editable via UI without code changes
Password reset via super admin bypasses email — directly overwrites the user's passwordHash. Use for forgotten admin passwords when the email reset flow isn't accessible. Settings currently hardcoded in components and email templates.
