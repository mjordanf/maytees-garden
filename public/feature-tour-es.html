Autenticación

Creación de Cuenta

Los nuevos clientes se registran en /auth/register. Las contraseñas se cifran con bcrypt en el servidor. Se envía un correo de bienvenida de inmediato al completarse el registro.

  • Nombre Completo, Correo, Contraseña (8+ caracteres), Teléfono (opcional)
  • La casilla del boletín activa el flujo de doble confirmación
  • Al enviar: POST /api/auth/register
  • Se almacena el hash bcrypt (rondas: 10) — nunca se guarda texto plano
  • Redirige a /portal al completarse correctamente
Correo de bienvenida enviado vía Resend al nuevo usuario. Si se marca newsletterOptIn, se crea un registro BoletínSubscriber con confirmed: false pendiente de confirmación por correo.

Autenticación

Inicio de Sesión

Proveedor de credenciales de NextAuth.js con estrategia de sesión JWT. Las sesiones duran 30 días. El rol se incluye en el JWT al iniciar sesión.

  • Correo + contraseña → POST /api/auth/callback/credentials
  • bcrypt.compare valida el hash de la contraseña
  • El callback JWT inyecta token.id y token.role
  • Olvidé mi contraseña → token de restablecimiento de 1 hora enviado por correo
  • Redirección: cliente→/portal, admin→/portal (enlace al Panel Admin en la barra lateral)
Redirección por rol: Todos los roles aterrizan en /portal. El superadmin puede navegar a /superadmin. Admin/staff ven un enlace "Panel Admin" en la barra lateral del portal. Los cambios de rol toman efecto en el próximo inicio de sesión (renovación del JWT).

Comercio Electrónico

Página del Carrito

El carrito en /shop/cart — revisa artículos, ajusta cantidades y procede al pago. Los datos se guardan en localStorage.

  • Persistencia en localStorage — no se requiere cuenta
  • El selector de cantidad está limitado a onlineStock
  • El ícono de papelera elimina el artículo; el selector de cantidad actualiza el subtotal en tiempo real
  • La insignia del carrito en la barra de navegación se actualiza en tiempo real a través de CartContext
  • El carrito se vacía al cerrar sesión
Límite de stock: Si un usuario tiene cantidad=5 y el admin baja el stock a 3, la próxima carga del carrito limita la cantidad a 3 y muestra una advertencia. Al continuar se inicia el Paso 1 del proceso de pago.

Comercio Electrónico · Pago Paso 1

Proceso de Pago — Paso 1: Contacto y Envío

Paso 1 de 3 en /shop/checkout — información de contacto y dirección de envío. Pre-rellenado desde la sesión si el usuario está conectado.

  • Nombre y correo pre-rellenados desde la sesión NextAuth
  • Obligatorios: Nombre, Correo, Dirección, Ciudad, Estado, ZIP
  • La dirección se envía a Shippo getRates() en el Paso 2
  • El botón Continuar está desactivado hasta que los campos obligatorios sean válidos
  • Verificación atómica de disponibilidad de horario al enviar el formulario final
Pago como invitado está completamente soportado — no se requiere cuenta. El carrito usa localStorage; se pueden hacer pedidos sin iniciar sesión. Los pedidos de invitados no aparecerán en el historial de pedidos del portal del cliente.

Comercio Electrónico · Pago Paso 2

Proceso de Pago — Paso 2: Método de Envío

El Paso 2 llama a Shippo en tiempo real para obtener tarifas del transportista según la dirección de envío ingresada y las dimensiones del paquete.

  • POST /api/store/shipping-rates → API de Shippo
  • Devuelve nombre del transportista, nivel de servicio, precio y días estimados
  • Tarifas ordenadas de menor a mayor precio
  • Tarifa plana de $12.99 como alternativa si Shippo no está configurado
  • El resumen del pedido se actualiza con el costo de envío seleccionado y el impuesto
Punto de fallo frecuente: Si Shippo no devuelve tarifas (clave API ausente o problema con la dirección), no aparecen opciones y el usuario no puede continuar. Asegúrate de que SHIPPO_API_KEY esté configurado y los campos de dirección estén completos.

Comercio Electrónico · Pago Paso 3

Proceso de Pago — Paso 3: Pago

El SDK de Pagos Web de Square renderiza un formulario de tarjeta en iframe. La tarjeta se tokeniza en el cliente; solo el token se envía al servidor — cumple con PCI.

  • El SDK de Square se carga desde web.squarecdn.com
  • El cliente tokeniza la tarjeta → sourceId
  • POST /api/store/checkout con sourceId + carrito
  • El servidor valida el stock, cobra a Square y decrementa onlineStock
  • La transacción atómica de Prisma previene la sobreventa
Tarjeta de prueba (sandbox): 4111 1111 1111 1111, cualquier fecha futura (p.ej. 01/29), cualquier CVV (123), cualquier ZIP. Asegúrate de que SQUARE_ENVIRONMENT=sandbox esté en desarrollo.

Comercio Electrónico · Post-Compra

Página de Confirmación del Pedido

Tras el pago exitoso, el cliente llega a /shop/order/[id] — el resumen completo del pedido con descarga de archivo ICS y confirmación por correo enviada automáticamente.

  • Formato del número de pedido: MG-XXXXXX (único, basado en CUID)
  • Correos de confirmación: cliente (resumen del pedido) + admin (alerta de nuevo pedido)
  • Agregar al Calendario — descarga el archivo .ics
  • La página es accesible por el ID del pedido en la URL (no requiere inicio de sesión)
  • StoreOrder.status → processing después del pago
El stock se decrementa atómicamente en una transacción Prisma — si el pago es exitoso pero la actualización del stock falla, la transacción se revierte y el error se muestra. El admin también recibe un mensaje de tipo order-alert en la Bandeja de Entrada.

Reservar una Consulta — Flujo Completo

Asistente de 4 pasos en /booking — seleccionar servicio, elegir fecha/hora, preferencia de reunión e ingresar datos de contacto. No se requiere cuenta.

  • Paso 1: Elegir servicio (de los registros Service activos)
  • Paso 2: Calendario — solo se muestran fechas realmente disponibles (plantillas + excepciones)
  • Paso 3: Preferencia de reunión (presencial / FaceTime / WhatsApp / Google Meet)
  • Paso 4: Datos de contacto — pre-rellenado desde la sesión si el usuario está conectado
  • Crea Booking { status: "pending" } y dispara 2 correos
El tipo de horario de DisponibilidadTemplate.type controla qué opciones de preferencia aparecen: "in-person" → solo presencial, "video" → solo opciones de video, "both" → se muestran las cuatro opciones.

Portal del Cliente — Citas y Mensajes

Los clientes gestionan sus reservas en /portal/appointments y envían mensajes a Maytee en /portal/messages.

Bandeja de Entrada del Administrador — Detalle Completo

La bandeja de entrada unificada en /admin/inbox agrega 4 tipos de mensajes: mensajes del portal del cliente, alertas de reservas, formularios de contacto y alertas de pedidos.

  • Pestañas: Todos / No Leído / Mensajes / Alertas de Reservas / Formularios de Contacto / Pedidos

  • La alerta de reserva enlaza a /admin/bookings
  • La alerta de pedido enlaza a /admin/orders
Responder envía correo vía sendLeadResponder() o sendCustomerMessageAlert() según el tipo de mensaje. El asunto y el cuerpo los redacta el admin. La respuesta se envía al correo del remitente original.

Panel Admin · Reservas

Gestión de Reservas — Flujo de Confirmación

Ciclo de vida completo en /admin/bookings — confirmar reservas pendientes, seleccionar tipo de consulta, sincronizar el calendario de Outlook y cancelar si es necesario.

  • Filtrar por: Todos / Pendiente / Confirmado / Completado / Cancelado
  • Confirmar → modal: seleccionar tipo de consulta, pegar enlace de video si es videoconferencia
  • Al confirmar: se crea un evento de calendario en Outlook vía Microsoft Graph
  • El cliente recibe un correo de confirmación con marca (formato presencial o video)
  • Cancelar: estado → cancelado, evento del calendario eliminado, bandeja de entrada del admin notificada
La sincronización del calendario es flexible — si faltan las credenciales de Azure (MICROSOFT_TENANT_ID etc. no configurados), isConfigured() devuelve false y las reservas aún se confirman correctamente sin crear eventos de calendario.

Gestión de Disponibilidad

Configura el horario semanal de reservas en /admin/availability — qué días están abiertos, horarios de inicio/fin, duración del turno y tipo de reunión por día.

  • Cuadrícula de 7 días: activar/desactivar cada día
  • Por día: Hora de Inicio, Hora de Fin, Duración del Turno (minutos) y Tipo
  • El Tipo controla las opciones de preferencia del cliente (presencial / video / ambos)
  • Botón de acceso rápido "Aplicar Lun–Vie" para configuración rápida
  • Los cambios son inmediatos — afectan el calendario de reservas en vivo
Sin plantilla = cerrado. Si el domingo no tiene DisponibilidadTemplate (o el interruptor está apagado), ese día aparece completamente en gris en el calendario de reservas. Una duración de turno de 60 minutos genera turnos por hora desde el inicio hasta el fin.

Fechas Bloqueadas

La pestaña Fechas Bloqueadas crea registros DisponibilidadOverride que ponen en gris fechas específicas en el calendario de reservas, independientemente de la plantilla semanal.

  • Selector de fecha + motivo opcional (solo visible para el admin)
  • Las fechas bloqueadas aparecen como no disponibles en el calendario /booking
  • Las reservas existentes en fechas bloqueadas NO se cancelan
  • Eliminar con el botón × → DELETE /api/availability/overrides/[id]
  • El campo de motivo es para referencia interna — no se muestra a los clientes
Caso de uso: Bloquear semanas de vacaciones, días festivos o días en que Maytee tiene otros compromisos. El registro de excepción tiene isBlocked: true, que el endpoint de turnos verifica antes de devolver los horarios disponibles.

Gestión del Catálogo de Plantas

CRUD completo para el catálogo de plantas en /admin/plants — edición de stock en línea, carga automática de imágenes de Wikipedia y más de 90 plantas precargadas.

Panel Admin · Pedidos

Gestión y Cumplimiento de Pedidos

Cumplimiento completo de pedidos en /admin/orders — ver pedidos, generar etiquetas de Shippo, marcar como enviado y emitir reembolsos de Square.

  • Filtrar por estado: Pendiente / En Proceso / Enviado / Entregado / Cancelado
  • Generar Etiqueta: obtiene tarifas de Shippo → compra → PDF de etiqueta + número de seguimiento guardados
  • Marcar como Enviado → sendEnvíoConfirmation() con número de seguimiento
  • Cancelar → la API de reembolso de Square se llama automáticamente si existe el pago
  • StoreOrder.trackingNumber incluido en el correo de envío
La compra de la etiqueta es definitiva — Shippo cobra por la etiqueta incluso si no se usa. Siempre verifica la dirección de envío antes de comprar. Los reembolsos de Square se emiten vía POST /api/store/orders/[id]/refund.

Sistema · Correo

Resumen del Sistema de Notificaciones por Correo

Todos los correos transaccionales se envían vía Resend desde noreply@mayteesgardencenter.com. El dominio está verificado vía DNS de GoDaddy. 15 disparadores de correo distintos en todo el sistema.

  • Todas las funciones están en src/lib/email.ts
  • Respaldo seguro: si RESEND_API_KEY no está configurado, solo registra en la consola
  • El recordatorio de 24 horas se ejecuta vía cron de Vercel a las 10 AM UTC diariamente
  • Boletín: solo los suscriptores con confirmed: true reciben difusiones
  • Remitente: "Maytee's Garden <noreply@mayteesgardencenter.com>"
Nivel gratuito: Resend ofrece 3,000 correos/mes y 100/día — suficiente para el volumen típico de un centro de jardinería boutique. Los tokens de restablecimiento de contraseña expiran después de 1 hora. Prueba de correo en /admin/test-email.

Sistema · Calendario

Integración de Calendario — Cómo Funciona

La API de Microsoft Graph sincroniza las reservas confirmadas al calendario de Outlook de info@mayteesgardencenter.com usando credenciales de cliente (no requiere inicio de sesión de usuario).

  • App de Azure AD: "Maytees Garden Calendar" registrada en portal.azure.com
  • Permiso: Calendars.ReadWrite (Aplicación, consentido por admin)
  • Auth: flujo de credenciales de cliente → token de acceso válido ~1 hora
  • Crear al confirmar · Actualizar al editar · Eliminar al cancelar
  • Operación nula graceful si las variables de entorno no están configuradas — las reservas siguen funcionando
El evento incluye: nombre del cliente, correo, teléfono, ZIP, servicio, tipo de consulta, enlace de videollamada (si es video), notas del cliente y un recordatorio de calendario de 60 minutos. El ID del evento se guarda como Booking.calendarEventId.

Súper Admin · Usuarios

Súper Administrador — Gestión de Usuarios

CRUD completo de usuarios en /superadmin/users — crear cuentas, editar roles, restablecer contraseñas y eliminar usuarios. Las insignias de rol están codificadas por color según el nivel.

  • Ámbar = Superadmin · Verde = Admin · Azul = Staff · Gris = Cliente
  • Nuevo Usuario: crear con nombre, correo, contraseña temporal, rol y teléfono
  • Editar: actualizar nombre, rol, teléfono — el cambio de rol toma efecto en el próximo inicio de sesión
  • Eliminar: usuario borrado; las reservas/pedidos asociados establecen userId = null
  • Todas las acciones llaman a /api/admin/users y /api/admin/users/[id]
Las sesiones JWT no se invalidan de inmediato al cambiar el rol — el rol actualizado toma efecto cuando el JWT actual del usuario expira o el usuario cierra sesión y vuelve a iniciarla. Informa a los usuarios que vuelvan a iniciar sesión tras un cambio de rol.

Súper Admin · Restablecer Contraseña y Configuración

Súper Administrador — Restablecer Contraseña y Cambiar Roles

Dos operaciones críticas del súper admin: restablecer contraseñas de usuarios fuera de banda y ver (actualmente de solo lectura) la configuración del sitio web.

  • Restablecer Contraseña: ingresar nueva contraseña temporal → se almacena bcrypt.hash en la base de datos
  • Comunicar la contraseña temporal al usuario fuera de banda (canal seguro)
  • El usuario debe cambiarla vía el flujo de Olvidé mi Contraseña tras el primer inicio de sesión
  • Página de configuración: nombre del negocio, dirección, teléfono, correo y horario (solo lectura)
  • Fase 2: configuración editable vía interfaz sin cambios de código
El restablecimiento de contraseña vía súper admin omite el correo — sobreescribe directamente el passwordHash del usuario. Úsalo para contraseñas de admin olvidadas cuando el flujo de restablecimiento por correo no está disponible. La configuración actualmente está codificada en los componentes y plantillas de correo.
